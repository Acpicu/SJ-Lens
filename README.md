# SJ Lens

[![release](https://img.shields.io/badge/release-v2.1.0-22D3EE)](https://github.com/RadarPika/SJ-Lens/releases)
[![license](https://img.shields.io/badge/license-MIT-3B9EFF)](LICENSE)

安卓端红队情报工具：围绕一个**目标**收集公开线索、登记成结构化记录、按证据强度交档。

场景是网络侦探竞赛（蓝队藏信息，红队拼图）。蓝队软件另做，本仓库只是红队这一侧：

- 平台动态聚合：把目标在 B站 / 抖音 / 快手的公开内容收进一个地方，看谁在什么时候发了什么
- 跨平台关联度评估：判断几个号能不能被认定为同一个人，以及下一步该去取什么证
- 数据本：一条记录 = 一条可陈述事实，带出处、信源评级、置信度、状态，可导出 Markdown 简报

**数据全部存本机**，不上传任何服务器，没有账号体系、没有埋点、没有第三方 SDK。

---

## 能做什么

| 模块 | 能力 | 说明 |
|---|---|---|
| **B站** | 作品 + 动态列表，更新检测，后台自动跑 | 公开接口，**需登录** |
| **抖音** | 主页内容预览，按作品总数比对更新 | 读网页渲染结果，不碰接口签名 |
| **快手** | 同上 | 同上 |
| **数据本** | 结构化记录 + 冲突/缺口检测 + Markdown 报告 | 每个目标一本，可按全部目标汇总 |
| **关联度评估** | 跨平台昵称 / 头像 / 简介相似度打分 | 纯本地计算，不联网 |

### 数据本

一条记录不是一段自由文本，而是「分类 + 字段 + 值 + 出处 + 评级 + 置信度 + 状态」：

- 分类：账号、身份、联系、单位、地点、时间、关系、内容、行为、其他
- 信源评级：Admiralty `A–F` × `1–6`，界面直接把 `B2` 读成「通常可靠 · 可能为真」
- 状态：待验证 / 已证实 / 已推翻，列表里一键切换
- 同一字段出现两个不同值 → 概览和报告里点名 **冲突**，列出记录号
- 真实身份 / 联系方式 / 单位 / 城市 / 作息 / 关系人 缺哪类，概览直接列 **缺口**
- 导出按 已证实 / 待验证 / 已推翻 分节的 Markdown，交档时直接贴

### 其他

- **目标卡片**：一个目标一个卡片，可自定义头像；长按排序
- **最近检查**：上一轮检查发现的新内容汇总，每轮整体覆盖
- **自动检查**：进应用跑一轮 + 每 60 分钟后台跑一轮，发现新内容发通知
- **导出 / 导入**：目标、账号、数据本合成一份 JSON，换机或交接用

## 已知限制（务必先看）

0. **B站 必须登录才能稳定使用。**
   这是 B站 自己的运维要求，不是本应用的限制：未登录时接口很容易返回 `412 / -352`。
   登录入口：`设置 → 账号与登录 → B站`。应用不接触你的密码，登录在官方页面内完成。

1. **更新检测未经完整验证。**
   逻辑是「平台给的计数变大就报更新」，各平台计数口径可能变动，
   **请自行在主页核对数量**。界面里也写明了这一点。

2. **三个平台的作品列表都抓不全。**
   - **B站**：接口按页返回，目前只取第一页，也就是最近 **30 条**
   - **抖音 / 快手**：作品列表是无限懒加载，只能拿到首屏已渲染的封面

   分页/继续加载还没做。**这不影响更新检测** —— 检测看的是总数和快照比对。

3. **抖音 / 快手不能在后台自动检测。**
   读取网页需要真实渲染窗口，后台任务没有窗口。

4. **平台计数可能包含非公开内容。**
   「互关好友可见」的草稿箱内容会被算进总数，导致条数比公开可见的多 1～2 条。

5. **关联度评估只吃你手填/看到的公开资料**，不做人脸比对、不做照片地理定位、不读通讯录。

## 实现要点（踩过的坑）

1. **平台网页会主动跳 App 深链。**
   抖音主页加载完会立刻跳 `snssdk1128://user/profile?...`，WebView 跟着跳就是
   `ERR_UNKNOWN_URL_SCHEME`，整个页面被错误页顶掉。
   解决：`shouldOverrideUrlLoading` 里只放行 `http(s)`。

2. **WebView 视口不能太小。** 1×1 像素会让站点渲染成空壳，DOM 里没有任何作品节点。

3. **不能用 `alpha = 0` 隐藏铺满屏幕的 WebView。** 它仍然接收触摸事件，会把整个界面的点击吞掉。
   要隐藏又不吃点击，用 `View.INVISIBLE`。

4. **B站 接口需要 WBI 签名 + 设备指纹。** 缺 `buvid3` 返回 `412`，缺 `dm_img_*` 返回 `-352`，
   并且必须先访问一次网页把 Cookie 暖起来。

5. **抖音的作品 ID 不在 DOM 里。** 身份标识改用封面图 URL 的文件名主干，更新判断用作品总数。

6. **分享出来的链接可能不是网页链接。** `PlatformUrls` 会从 `snssdk1128://` 里抠 `sec_uid`
   还原成网页地址。

## 构建

需要 JDK 17 与 Android SDK（compileSdk 36）。

```bash
# 调试包
./gradlew assembleDebug

# 正式包（需先准备 keystore.properties）
./gradlew assembleRelease
```

### 签名配置

在项目根目录新建 `keystore.properties`（**不要提交到仓库**）：

```properties
storeFile=keystore/your-release.jks
storePassword=你的密码
keyAlias=你的别名
keyPassword=你的密码
```

生成 keystore：

```bash
keytool -genkeypair -v -keystore keystore/your-release.jks \
  -alias youralias -keyalg RSA -keysize 2048 -validity 10000
```

**没有这个文件也能构建** —— 会自动退回 debug 签名，只是不能覆盖安装到已发布的包上。

## 项目结构

```
app/src/main/java/com/sj/followclip/
├── data/
│   ├── local/        持久化：folders.json（目标+账号+数据本）、快照、待确认池
│   │   ├── LedgerStore.kt   数据本：记录模型、评级、冲突/缺口分析、Markdown 报告、旧数据迁移
│   │   └── JsonStore.kt     备份编码/解码（含数据本）
│   ├── osint/        关联度评估与内容统计引擎（纯 Kotlin，无 android 依赖）
│   ├── source/bili/  B站接口：WBI 签名、Cookie、检查逻辑
│   ├── source/web/   抖音/快手：隐藏 WebView 抓取
│   └── work/         WorkManager 定时任务
├── domain/model/     数据模型
├── ui/
│   ├── ledger/       数据本：目标页、总览页、报告预览（三屏共用一套记录卡）
│   ├── osint/        关联度评估
│   └── ...           首页、目标详情、平台页、设置
└── util/             通知、Cookie、头像存储
```

技术栈：Kotlin + Jetpack Compose + Material 3，**零第三方网络/图片/数据库库**
（HTTP 用 `HttpURLConnection`，JSON 用 `org.json`，图片缓存自己写的 `LruCache`）。

## 隐私

- 不收集任何数据，不联网上传任何内容。

- 数据本与截图都存应用私有目录，卸载即彻底清除。
