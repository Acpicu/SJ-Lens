# SJ Lens · OSINT 模块使用说明

## 一、这轮加了什么

| 功能 | 入口 | 说明 |
|---|---|---|
| 曝光审计 | 设置 → 曝光审计 → 自身曝光审计 | 把自己在各平台的公开资料填进去，算出「别人把这些号认成同一个人的难度」 |
| 内容统计 | 打开某个 B站账号的作品页，列表最上方 | 用已抓到的条目当场算发布节奏：间隔、集中时段、星期分布 |

两个功能都**不联网、不申请权限、不上传**。曝光审计的数据只在页面内存里算，退出页面即丢。

## 二、安装

```powershell
# 手机连电脑后，在项目根目录
adb devices                                  # 确认设备在线
adb install -r app\build\outputs\apk\release\app-release.apk
```

- debug 包（12.57 MB）和 release 包（1.77 MB）都已经带上新功能。
- 如果之前装的是别的签名版本，先卸载再装（签名不同会冲突）。

## 三、曝光审计怎么用

1. 打开 App → 底部「设置」→ 下滑到「曝光审计」→ 点「打开」
2. 三个平台各填一行，只需要填你**自己**的：
   - **昵称**：该平台上你显示的昵称（必填，留空该平台不参与计算）
   - **简介**：个人签名 / 简介里的文字（可不填，用于找共用特征词）
   - **这个主页能被搜到**：用别人手机或退出登录，搜你的昵称能不能直接搜到这个主页
   - **头像和其他平台是同一张**：三个平台用的是同一张头像就打开
3. 下方卡片实时出结果，不用点计算

### 分数怎么读

| 分数 | 等级 | 含义 |
|---|---|---|
| 0–24 | 低 | 跨平台不容易被认成同一个人 |
| 25–59 | 中 | 有人愿意花几分钟就能串起来 |
| 60–100 | 高 | 三个号基本等于同一个身份公开挂着 |

点「展开明细」看每一项命中了什么、加了多少分，以及对应的收敛建议。

### 权重表（想理解分数来源就看这个）

| 特征 | 加分 |
|---|---|
| 两个平台昵称完全相同 | +30 |
| 一个昵称包含另一个 | +18 |
| 昵称只差一个字符 | +12 |
| 头像是同一张图（哈希汉明距离 0） | +25 |
| 头像接近（≤8 位差异，改过压缩/裁切） | +15 |
| 简介有共用词（每对平台 +8，上限 16） | ≤+16 |
| 两个以上平台能被直接搜到 | +10 |
| 只有一个平台能被搜到 | +5 |

## 四、AI 解读怎么用（自带 Key）

1. 设置 →「AI 解读」→ 填三项：接口地址（填到 `/v1` 这一级，例如 `https://HOST/v1`）、模型名、API Key → 点「保存」
2. 打开某个 B站账号的作品页 → 先点「检查更新」拉一次 → 点「AI 解读」
3. 弹窗给出四行结论：主题分布 / 更新节奏 / 内容类型 / 数据局限

**发出去的东西**：平台名、统计量（条数、跨度、中位间隔、最活跃星期、集中时段、标题占比）、脱敏后的标题（最多 40 条、每条截断 60 字）。

**不发的东西**：主页链接、Cookie、设备标识、头像图片、任何私域内容。

**发送前自动脱敏**（`AiBrief.sanitize`）：`http(s)://` 链接 → `[链接]`；邮箱 → `[邮箱]`；`@提及` → `[提及]`；11 位手机号 → `[手机号]`；11 位以上连续数字 → `[数字]`。

**提示词硬约束**（`AiBrief.SYSTEM_PROMPT`）：只允许输出主题分布、更新节奏、内容类型、数据局限四类；明确禁止推测真实姓名、学校、单位、住址、定位、联系方式、人际关系、心理状态、健康、政治倾向；材料不足必须写「材料不足」。总输出不超过 200 字。

Key 存在本机 SharedPreferences（`sj_ai_config`），不上传、不代理、不写入导出文件；设置页可一键「清除」。

## 五、内容统计怎么用
1. 首页 → 点一个人 → 点他的 B站账号 → 点「检查更新」拉一次数据
2. 列表最上方就是统计卡

看到的是：样本条数与时间跨度、中位/平均发布间隔、最集中的 3 小时时段、最活跃星期、星期分布柱状图，以及数据质量提示（样本不足、跨度不够、疑似批量连发）。

抖音/快手目前没有这个面板：它们只拿得到首屏少数条目，算出来的分布没有意义，不硬凑。

## 六、边界（这轮没做，也不会做）

- 不做第三方个体的资料聚合、身份归因（判定两个号是同一个人）、人脸比对、照片定位
- 不做手机号 / 邮箱 / 身份证反查
- 不抓私域数据（私信、好友、关注列表、非公开内容）
- 不绕过登录或风控去扩容抓取

理由不是道德说教，是这类功能一旦落到"某个具体的人"身上，性质就从分析工具变成跟踪工具，且会把开发者一起拖进责任里。

## 七、还能继续做的（同样有技术含量，主体仍是自己 / 公开实体）

1. **自查账号占用**：拿你自己的常用昵称跑一遍站点清单，看哪些站还留着旧账号（Sherlock 那类工具的自查用法）
2. **搜索算子速查**：把自己名字 / 昵称 / 旧邮箱做成一组固定检索式，定期看搜索引擎收录了什么
3. **公开内容统计扩展到动态页**：动态也接同一套引擎
4. **导出脱敏**：导出的 JSON 去掉主页 URL 明文

## 八、已知问题
