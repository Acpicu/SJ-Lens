# SJ Lens 用户手册

> 单机版公开信息工作台。所有数据存在本机，无账号体系、无云同步、无上传。
> 版本：1.0.0+ · 安装包 1.79 MB · minSdk 24（Android 7.0+）

---

## 一、一句话定位

**SJ Lens 是一个本地运行的「公开信息记录本 + 抓取器」**：把你在 B站 / 抖音 / 快手 关注的公开主页聚到一起看更新，用统计和笔记把观察记下来，证据编号并以 Markdown 报告导出。

它不做判断。判断、结论、置信度都由人来写。

## 二、能做什么（功能总表）

| # | 功能 | 入口 | 做什么 | 数据去哪 |
|---|---|---|---|---|
| 1 | 文件夹（人物）管理 | 首页 → 右下角 + | 一个人一个文件夹，备注名自己起，可自定义头像 | 本机 JSON |
| 2 | 添加平台账号 | 进文件夹 → 右下角 + | 一个文件夹可挂多个平台账号，同平台可挂多个号 | 本机 JSON |
| 3 | 检查更新 | 首页「检查」/ 账号页「检查更新」 | B站走原生接口，抖音/快手走隐藏 WebView 读 DOM | 本机快照 |
| 4 | 「最近检查」汇总 | 底部第二个页签 | 每轮检查整体覆盖，看到本轮谁发新内容 | 本机 SharedPreferences |
| 5 | 后台检查 + 通知 | 自动，每 60 分钟 | 仅联网时跑；有新内容发通知；仅 B站支持后台 | 系统通知 |
| 6 | 定时提醒 | 账号页设置 3/7/14 天 | 到期提醒你手动去看一眼（抖音快手只能这样兜底） | 本机 |
| 7 | 内容统计 | 账号作品页 / 动态页顶部 | 中位/平均发布间隔、集中时段、最活跃星期、7 天分布柱状图、数据质量提示 | 当场算，不落盘 |
| 8 | 曝光审计（自查） | 设置 → OSINT → 自身曝光审计 | 填自己各平台资料，算跨平台「可被串成同一人」的关联度 0–100 | 仅内存，退出即丢 |
| 9 | 关联图 | 同上，页面中部 | 节点=平台，边=命中的关联，线宽=权重，红色=强关联 | 仅内存 |
| 10 | 笔记 | 文件夹内「笔记」卡 | 每文件夹一条自由文本，点保存才落盘 | 本机 SharedPreferences |
| 11 | 证据条目 | 文件夹内「证据条目」 | E-001 起编号，记来源 / SHA-256 / Admiralty 等级 / 备注 / 截图 | 本机 SharedPreferences + 私有目录 |
| 12 | 截图快照 | 证据页「附截图」 | 选图后复制进私有目录，自动算 SHA-256 填进证据 | 应用私有目录 |
| 13 | 待验证清单 | 证据页下半部分 | T-01 起编号，每条写「查什么 + 查到就能证实/推翻」，可标已证实/已推翻 | 本机 SharedPreferences |
| 14 | 报告导出 | 证据页右上「导出」 | 四段式 Markdown：结论 / 证据 / 置信度 / 待验证清单 | 你选的 .md 文件 |
| 15 | 现场手册 | 设置 → OSINT → 现场手册 | 7 章方法论：证据链、信源分级、三源法则、误判清单、OPSEC、边界、报告写法 | 内置文本 |
| 16 | 数据备份 | 设置 → 数据 → 导出/导入 | 全量 JSON 备份，换手机用 | 你选的 .json 文件 |

## 三、快速开始

1. 安装：`adb install -r app-release.apk`
2. 首次启动弹一次耗电白名单引导，按提示加白名单（不加后台检查会被系统掐掉）
3. 首页右下角 **+** → 建一个文件夹（比如同学名字），可顺手设头像
4. 进文件夹 → 右下角 **+** → 选平台，粘贴主页链接或 UID
   - B站要登录才稳定：设置 →「账号与登录」→ B站登录，只保留 `SESSDATA`
5. 首页点「检查」，或进账号页点「检查更新」
6. 看内容统计 → 写笔记 → 记证据 → 导出报告

## 四、三个平台的实际差异（写清楚了，别当 bug）

| | B站 | 抖音 | 快手 |
|---|---|---|---|
| 取数方式 | 原生 HTTP 接口（WBI 签名 + 设备指纹） | 隐藏 WebView 读 DOM | 隐藏 WebView 读 DOM |
| 作品 ID | 有（bvid） | **拿不到**，用封面图文件名做标识 | 同左 |
| 更新判断 | 条目差集比对 | 作品总数 `aweme_count` 变化 | 同左 |
| 列表完整性 | 接口第一页 30 条 | 首屏预览（懒加载，抓不全） | 首屏预览 |
| 后台自动检查 | 支持 | **不支持**（需要真实渲染窗口） | 不支持 |
| 内容统计 | 有 | 无（样本太少，不硬凑） | 无 |

**已知限制（设计如此，不是待修 bug）**
- 抖音/快手作品列表永远只有首屏，这是平台无限懒加载决定的
- 页面显示的「作品 27」是四舍五入展示值，会差 1–2；只有接口里的 `aweme_count` 精确
- 首次检查只建基线，不报「新」
- B站风控命中后冷却 5 分钟并整体中止，不会硬刷

## 五、内容统计怎么看

样本条数、时间跨度、中位/平均发布间隔、集中时段（连续 3 小时窗口）、最活跃星期、星期分布柱状图。

**数据质量兜底**会自动写进提示：样本<5 条、时间跨度<7 天、1 小时内连发（疑似批量发布）、只有 1 条样本。看到这些提示就别把结论当定论。

## 六、曝光审计怎么用（自查）

**主体是你自己。** 填你自己在各平台的公开资料，看别人把这些号认成同一个人的难度。

| 入口 | 设置 → OSINT → 自身曝光审计 |
|---|---|
| 输入 | 每个平台：昵称（必填）、简介、是否可被搜到、头像是否与其他平台同一张 |
| 输出 | 0–100 关联度 + 等级（低/中/高）+ 命中因子明细 + 收敛建议 + 关联图 |
| 存储 | **只在内存**，退出页面即丢，不写盘 |

权重表：

| 特征 | 加分 |
|---|---|
| 两平台昵称完全相同 / 包含关系 / 差一个字符 | +30 / +18 / +12 |
| 头像是同一张图 / 近似（汉明距离≤8 位） | +25 / +15 |
| 简介有共用特征词（每对平台 +8，上限 16） | ≤+16 |
| 两个以上平台能被直接搜到 / 只有一个 | +10 / +5 |

分数档位：<25 低、<60 中、其余高。「复制报告」把结果复制成纯文本，方便自查留档。

## 七、笔记与证据（核心工作流）

### 笔记
文件夹内「笔记」卡，一条自由文本。点「保存」才写盘，状态显示「已保存/未保存」。「清空」立即删除。

### 证据条目
1. 文件夹内点「证据条目」
2. 填来源（URL / 平台 / 页面标题）、信源等级（Admiralty，如 `B2`）、备注（这条能证明什么）
3. 需要留图点「附截图」→ 选图 → 自动复制进私有目录并算 SHA-256 自动填入
4. 点「登记」→ 得到 `E-001`、`E-002`……
5. 「导出」→ 选保存位置 → 得到 .md 报告

**编号规则**：序号存在 `seq_<personId>`，只增不减。删掉 E-002 后再登记是 E-003，报告引用不会错位。

### 待验证清单
每条写两件事——要验证什么、查什么就能证实或推翻。状态可切「已证实 / 已推翻 / 重置」。

### 报告结构（导出结果）

```
# 分析记录 · 名称
## 一、结论        ← 证据条目页顶部「结论」框，可保存到笔记
## 二、证据        ← 每条 E-xxx：时间 / 来源 / SHA-256 / 截图 / 备注
## 三、置信度      ← 留空占位，必须人工填写
## 四、待验证清单  ← [ ] 未验证 / [x] 已证实 / [x] 已推翻
```

置信度故意不自动打分：那是判断，不该由记录工具代劳。

## 八、现场手册（内置 7 章）

1. 证据链与编号（E-001 只增不改、三件套：原文件 + SHA-256 + 采集时间）
2. 信源可靠性分级（Admiralty A–F / 1–6，记录格式如 `B2`）
3. 三源法则（原始出处 / 独立第二源 / 时间戳互证）
4. 常见误判清单（同名不同人、头像盗用、感知哈希碰撞、时钟只能推到时区、互关可见造成假阳性）
5. 操作安全（环境隔离、不互动、不下载可执行文件、截图也可能被反向检索）
6. 边界
7. 报告写法（结论/证据/置信度/待验证 四段式）

## 九、数据在哪、怎么清

| 数据 | 位置 | 清除方式 |
|---|---|---|
| 文件夹 / 账号 | `filesDir` 下 JSON | 设置 → 清除全部本地数据 |
| 抓取快照 | SharedPreferences `video_snapshots` | 同上 |
| 最近检查结果 | SharedPreferences | 设置 → 数据 → 最近检查结果 → 清空 |
| **笔记** | SharedPreferences `sj_notes` | ⚠️ 目前「清除全部数据」**不会**清笔记，需进文件夹手动清空 |
| **证据 / 待验证** | SharedPreferences `sj_evidence` | ⚠️ 同上，需进证据页逐条删除 |
| **截图文件** | `filesDir/evidence/<personId>/` | 卸载应用时一并删除 |
| B站登录态 | SharedPreferences（仅 SESSDATA） | 设置 → B站「退出」 |

**没有任何数据上传到服务器。** 应用不申请存储、通讯录、定位、相机等权限，只有 `INTERNET` 和 `POST_NOTIFICATIONS`。

## 十、明确不做的

- 不做跨平台身份判定（「这两个号是同一个人」）——这类判断只记在你自己的笔记里，工具不给结论
- 不做人脸比对、照片定位、Exif 提取
- 不做手机号 / 邮箱 / 身份信息反查
- 不抓私域内容（私信、好友、关注列表、非公开内容）
- 不绕过登录或风控扩容抓取
- 不对第三方建立长期档案

## 十一、常见问题

**Q：抖音/快手白屏或抓不到？**
页面会跳 `snssdk1128://` 深链，应用只放行 http(s)。同时 WebView 必须按真实尺寸渲染（1×1 视口会被判为异常直接空壳）。这两点已处理；仍抓不到就点账号页右上角 🌐 看真实网页，用 `adb logcat -s SJExtract` 看日志。

**Q：B站一直 412 或 -352？**
未登录或设备指纹缺失。去设置登录 B站；命中风控会冷却 5 分钟。

**Q：数据统计说「样本不足」？**
抖音快手本来就只有首屏；B站只有第一页 30 条。分页未实现。

**Q：导出的报告没有置信度？**
故意留空，需要你自己写等级 + 一句理由。

**Q：换手机怎么迁移？**
设置 → 导出数据 → JSON 文件。注意：**JSON 只含文件夹与账号**，笔记和证据条目不在里面。

## 十二、构建

```powershell
# 需要 JDK 17 + Android SDK
.\gradlew.bat assembleDebug      # 调试包 ~12 MB
.\gradlew.bat assembleRelease    # 正式包 ~1.79 MB（R8 压缩）
```

- 项目在中文路径下，`gradle.properties` 已设 `android.overridePathCheck=true`
- `keystore.properties` 存在则用正式签名，否则自动退回 debug 签名
- ⚠️ 交接报告文档里明文写了 release keystore 的 alias 与密码，若该文档外发过，签名密钥按泄露处理
